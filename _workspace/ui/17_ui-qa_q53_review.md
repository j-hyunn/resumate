### UQ-600 상세

요건 없는 JD + `consent_required`로 시작한다.

1. 진입: `gateBlocked = true` → `entryStep = false` → 설정 화면 + 별도 "AI에게 맡기기" 버튼. 여기까지 명세와 같다.
2. 누름 → C-21 → 동의: `markConsentGiven` → `consent.required = false` → `gateBlocked = false`.
3. `entered`는 여전히 false이고 `extractFirst` prop도 그대로라 **`entryStep`이 true로 바뀐다**. 설정 화면이 사라지고 비활성 "새 경력기술서" + 스피너가 보인다.
4. 추출과 AI-11은 뒤에서 끝나지만 `rankNow`는 `setEntered(true)`를 부르지 않아(`:419-426`) 결과가 가려진 채 "새 경력기술서" 단계에 머문다. `router.refresh`도 없다.
5. 사용자가 다시 누르면 `enterNewCareerDescription`이 AI-11을 **한 번 더** 호출한다.

"직접 고르기" → "초안 생성" → 동의 경로도 3번의 화면 전환이 생긴다(그 뒤 S-19로 이동해 끝난다). 라디오로 다시 "AI에게 맡기기"를 고르는 경로는 같은 문제다. `?state=no-requirements-consent`에서도 재현될 것이다. 진입 단계 여부를 마운트 때 한 번만 정하거나, 게이트를 거친 실행이 `entered`를 켜면 풀린다.

## 기획 확인 필요

### A. QA가 새로 찾은 것

1. **`succeeded` + 요건 0개 (UQ-610).** AI 명세 AI-01: "요건 0개 + `is_likely_jd: false` → `not_a_jd`로 실패". `is_likely_jd: true` + 요건 0개는 정해지지 않았다. S-16: "추출은 됐는데 요건이 0개면 `not_a_jd` 문구". 02 S-15 ①: "(요건 0개로 `not_a_jd` 처리된 경우 포함)". 04 §2.6.1 조건 2: `extraction_status = 'failed'`. 앞 둘을 따라 C-20 "공고 원문 고치기"를 보이면 조건 2에 걸려 잠긴다. 이 조합을 실패로 저장할지 정해야 한다. 픽스처 AP 3·4·5가 이 상태다.
2. **같은 행 다시 시도와 입력 원인 답변 (UQ-612).** 04 §2.7.1은 "`begin_interview_evaluation`의 평가 대상에서 뺀다"이고 §2.9.1 R-63은 공급자가 다르면 평가를 전부 다시 연다. 대상 ≥ 1 혼합 세션의 같은 행 다시 시도에서 입력 원인 답변도 다시 여는지 정해지지 않았다.
