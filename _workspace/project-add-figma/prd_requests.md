# PRD v4.6 (PA-1~PA-4) — 다른 팀원 요청

- 작성: product-planner / 기준: `docs/planning/01-prd.md` v4.6, `_workspace/00_input/planning-decisions-project-add-figma.md`(확정 2026-11-03 (사용자))
- PRD에서 바뀐 위치는 PRD 9.5 표, 새 `[가정]` 9개는 9.5 아래 목록에 있다.

## 다른 팀원에게 요청

### ux-planner

1. **S-10 프로젝트 상세·S-44 산출물 상세 = 페이지 단위 저장**(PA-3, F-P1-03 (1), F-P1-18 (1)(2)). 이름 다이얼로그(C-23) 없이 빈 전체 페이지로 들어간다. 상단 바 = 로고 + "저장하기" + 계정 아이콘. STAR 다섯 칸과 머리 필드는 섹션별 "수정"(C-24)이 아니라 한 폼이다. C-24는 S-09·S-34·S-43 패널에만 남긴다.
2. **"저장하기" 사용 조건**: PRD `[가정]` = 프로젝트는 이름, 산출물은 제목이 있어야 저장된다. 다르게 정하면 알려 달라.
3. **이탈 확인·입력 보존을 페이지 단위로**(F-P1-06). 저장하지 않은 변경(직접 입력과 [반영]으로 채운 내용 모두)이 있으면 떠나기 전에 확인한다.
4. **첫 AI 메시지가 저장보다 먼저일 때**(F-P1-13 (1), F-P1-18 (6)): PRD `[가정]` = 이름(제목)이 비어 있으면 기본 이름(제목)으로 작성 중 행을 만들고, 저장하지 않고 떠나도 행과 대화는 남는다. 기본 이름 문구, 그 시점에 폼에 있던 다른 입력을 함께 저장할지는 UX가 데이터 모델과 함께 정해 달라.
5. **S-10 머리 필드**(PA-4, F-P1-03 (4)) = 프로젝트 종류 · 경험 유형 · 역량 · 진행 기간 · 진행 중. 근무·교육 프로젝트가 같고, 항상 입력 상태(드롭다운)로 둔다.
6. **S-44 정의**(PA-1·PA-2): 왼쪽 메뉴 없는 전체 페이지(S-10과 같은 셸), 이동 경로 "{프로젝트명} › {산출물 제목} › 산출물 상세", 머리 제목 = 산출물 제목 입력(별도 제목 칸 없음), 분류 드롭다운 없음, 산출물 민감정보 안내 1줄 유지, 오른쪽 "Resumate AI" 패널(대화 기록·새 대화·칩·입력창은 S-10 패널과 같음). 산출물 제안 카드의 [반영]에 **교체 / 덧붙이기** 선택을 둔다. 키가 없으면 패널은 F-AI-06 잠금, 본문 직접 입력은 그대로.
7. **AI 패널을 닫은 뒤 다시 여는 버튼 위치**를 정해 달라(결정 파일의 "함께 정리할 명세").
8. **독립 프로젝트 생성 진입**(C-22 → S-43)에서 C-23 이름 다이얼로그를 남길지 재검토해 달라. PRD는 F-P2-09에서 이 부분을 UX `[가정]`으로 두었다.
9. 삭제 확인 창(C-05): 산출물을 지우면 그 산출물의 AI 작성 대화도 함께 지워진다는 것을 보여 달라(F-COM-04, F-P1-18 (5)).

### ai-feature-designer

1. **산출물 작성 대화**(PA-1, F-P1-18 (6)~(8)) 명세를 AI 명세 v4.6에 정해 달라: 시작 인사, 빠른 버튼 칩, 본문 전체 초안 제안 스키마, 교체 / 덧붙이기. PRD는 계약 이름을 정하지 않고 "AI 명세 v4.6"으로만 가리킨다.
2. 가드레일은 F-P1-13 (5)·NFR-AI-02와 같다. PRD `[가정]` = 제안의 사실은 사용자 발화 + 그 독립 프로젝트의 저장된 정보·내용 + 현재 본문으로 추적할 수 있어야 하고, AI는 산출물 제목을 바꾸지 않는다. 참고 범위를 다르게 정하면 알려 달라.
3. **[반영] = 폼 채우기**(PA-3, F-P1-13 (6)(12)): "반영됨" 기록 시점(반영할 때 / 저장할 때)과, 반영 후 저장하지 않고 떠났을 때 제안 상태를 어떻게 둘지 정해 달라. 그리고 저장 전에 대화를 시작해 첫 메시지로 작성 중 행이 생기는 경로를 확인해 달라.
4. 메시지 상한 40, 대화 기록 여러 개, 사용량 미터 "AI 작성 대화" 집계(STAR·산출물 대화 합산 `[가정]`)가 산출물 대화에도 같은지 확인해 달라.
5. 산출물 대화에는 분류 추천이 없다(PA-2). 진행 중은 계속 제안하지 않는다(CR-20 세부 규칙).

### data-architect

1. `writing_chats` 소속을 **산출물**까지 넓혀 달라(PA-1). 산출물을 지우면 대화도 함께 지워지고(F-COM-04), 독립 프로젝트를 지우면 산출물과 그 대화가 함께 지워진다.
2. 반영 RPC(`apply_writing_chat_proposal`)의 "DB 즉시 저장" 의미를 PA-3에 맞게 고쳐 달라. [반영]은 화면 폼만 채우고, 저장은 일반 저장 경로("저장하기")로 한다. 산출물 본문의 교체 / 덧붙이기도 같다.
3. **작성 중 행 생성 시점** = 첫 저장 또는 첫 AI 메시지. `projects.name` not null과 `project_deliverables` 제목 필수 조건에서 기본 이름(제목)으로 행을 만드는 경로를 정해 달라(PRD 9.5 `[가정]` 2).
4. 산출물에는 분류 컬럼을 두지 않는다(PA-2). 지금 모델 그대로면 변경은 없다.

### spec-reviewer

1. PRD v4.6 9.5 표의 반영 위치로 UX·AI(v4.6)·DM 개정본을 대조해 달라. 특히 (a) "반영 = 폼 채우기, 저장하기로 확정"이 세 문서에서 같은지, (b) 첫 AI 메시지 때 행이 생기는 경로가 UX·DM에서 같은지, (c) CR-19의 남는 부분(독립 프로젝트 정보·내용은 대화 없음)이 유지되는지 확인해 달라.
