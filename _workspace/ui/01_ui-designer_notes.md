## 주요 판단과 이유

1. **초록 primary와 success 분리.** 둘 다 초록이면 "누를 수 있는 것"과 "끝난 상태"가 섞인다. primary는 청록 쪽(158°, 진한 #007044), success는 연두 쪽(140°)으로 색상각을 띄우고, 더 중요한 규칙으로 success는 채운 버튼·큰 면 금지, 항상 subtle 배지 또는 아이콘+글자로만 쓰게 했다(R-C2). 단계 점 색에서도 초록을 뺐다(R-C5). 포커스 링도 초록(`--ring` 158°)으로 맞췄다.
2. **AI 전용 보라 `--ai`.** 명세가 AI 상태의 구분을 가장 중요하게 다뤄서, AI가 "지금 하는 일"(진행·스트리밍·정리 갱신)과 "AI가 고른 것" 표시에만 쓰는 색을 하나 두었다. AI 실행 버튼은 일반 primary(버튼이 보라면 AI 버튼만 튀고 화면당 주 버튼 1개 규칙과 충돌).
3. **"근거 없음"은 회색.** `no_evidence`는 실패가 아니라 데이터 부재라 빨강을 쓰지 않음. C-09 게이트도 오류색 대신 primary-subtle 안내 카드.
4. **칩에 종류 아이콘 없음.** "회고 및 배운 점" 칩을 라벨로만 구분하라는 규칙을 지키려면 다른 종류에도 아이콘을 두지 않는 게 가장 단순하고 일관된다. 상태(변경됨/원본 삭제됨)만 아이콘.
5. **16px 본문 기준 폭.** 16px 한글 약 1em/자 → 42자 ≈ 42rem(672px)을 `max-w-prose-edit`로. 버튼 default·입력도 16px(iOS 확대 방지 겸). 메타 14px, 칩·카운트 12px(하한).
6. **입력 테두리 대비.** shadcn 기본 `--input`은 1.5:1로 WCAG 1.4.11 미달 → `--input`만 3.36:1로 진하게, 장식 구분선 `--border`는 연하게 유지.
7. **브레이크포인트.** 셸 1024(240px 메뉴 + 최소 784 콘텐츠), S-36 2단·S-19 패널 1280, 보드 탭 768. 보드는 넓은 화면에서도 보드 영역 안 가로 스크롤(페이지 가로 스크롤 없음).
8. **추가 의존성 회피.** vaul(Drawer)·react-day-picker(Calendar) 안 씀 → Sheet bottom, 네이티브 date/Select 두 개.

## 주요 판단

1. **잠금은 오류가 아니다.** C-18은 C-09와 같은 안내 카드 계열(`primary-subtle` 원 + `PlugZap`)로 그렸다. 경고색으로 그리면 키 없이 쓰는 사용자(정상 경로, UX-10)에게 화면 곳곳이 "문제 있음"으로 보인다. 결과 위에는 잠금을 덮지 않고(D-UX-15·D-36), 실행 버튼 자리만 점선 줄 인라인형으로 바꾼다.
2. **C-20은 톤을 둘로 나눴다.** 7원인 가운데 대부분(분당·일일 한도, 결제, 키, 모델, 입력)은 고장이 아니라 사용자가 기다리거나 손볼 일이라 warning으로 두었다. 공급자 장애와 시스템 오류만 destructive다. 그래서 ST-AI-FAILED 때와 달리 빨간 상자가 자주 뜨지 않는다. 아이콘은 원인마다 달라서 같은 노랑이어도 구분된다.
3. **C-19 경고 상태.** 리더 지시대로 invalid와 needs_check 모두 warning variant를 쓰고 아이콘·글자로 구분한다(TriangleAlert "키를 확인해 주세요" / CircleHelp "확인 필요"). 동작 차이는 실행 결과(C-20 여부)가 보인다.
4. **`AiRunButton`으로 UsageHint 자리를 대신했다.** "실행 버튼 + C-19 배지 + (다시 하기 주석)"을 한 컴포넌트로 묶어서, 영역별로 배지를 빠뜨리거나 위치가 달라지지 않게 했다. 키 없음, 무효, 확인 필요, 진행 중 상태 전환도 여기서 한 번에 처리한다.
5. **무료 등급 대기는 AI 보라로 보인다.** 자동 재시도 대기는 실패가 아니라 "아직 도는 중"이라서, C-03 카드 안에서 아이콘만 Hourglass로 바뀌고 색은 그대로다.
6. **L-01 상태 줄 위치.** NavSecondary 첫 항목(설정 위)에 두었다. 누르면 설정 다이얼로그의 AI 연결 섹션이 열리므로 설정과 같은 묶음이 자연스럽다. NavUser 위에 두면 계정 메뉴처럼 보인다.
7. **S-41 집중 화면.** 명세가 "S-40 위 전체 화면 단계"라고 해서, 넓은 화면에서는 사이드바 없이 X(그만두기)와 단계 표시만 남겼다. 공급자 사이트를 오가는 동안 위치를 잃지 않게 단계를 주소로 유지한다. 라우트 구성 가능 여부는 Q-5에 남겼다.
8. **토큰 추가 없음.** 모든 새 패턴을 기존 warning/destructive/success/info/ai/primary-subtle로 표현했다. badge에 `recommend` variant 하나만 더했다(새 색 아님, primary-subtle 재사용).
9. **삭제한 것.** UsageHint, LimitNotice, ST-LIMIT, C-09 10회 분기, "사용량은 차감되지 않았습니다", 횟수 문구. 각각의 대체는 9장 v2 행과 4장 표에 적었다.

2. **"처음부터 다시"는 경고가 아니다.** 감싼 Alert의 글자색에 `ArrowLeftRight` 아이콘만 붙인다.
3. **다시 시도 거부는 동작 줄만 바꾼다.** 실패 안내 위에 Alert를 또 쌓으면 원인이 둘처럼 보이기 때문이다(G-34).
4. **요청 안 경로의 대기는 C-20, 비동기 대기는 C-03.** 사용자가 다시 눌러야 하는 대기에는 보라 Hourglass를 쓰지 않는다.
5. **그만둔 것은 회색 PauseCircle.** 대화·면접 모두 AI 보라와 경고색을 쓰지 않는다. "다시 이어 하기"는 AI 호출이 없어 배지가 없다.
6. **S-10 빈 칸 강조는 primary 링.** 오류가 아니므로 destructive를 쓰지 않는다.
7. **흐린 종합 평가는 글자에 opacity를 걸지 않는다.** A-1 대비를 지키려고 글자는 muted-foreground로 낮추고, 칩·배지에만 opacity를 쓴다.
