# 기획 브리프

## 요청 경위

- 사용자: "기획 시작하자"
- 사전 대화 맥락 없음. `.claude/skills/resumate-planning/references/product-context.md`에 정의된 Resumate 제품 컨텍스트(3대 축: 경력 데이터 관리 / JD 기반 인사이트·채팅 / AI 모의 면접, 기술 스택: Next.js + Supabase + Claude)를 기반으로 신규 기획을 시작한다.

## 범위

초기 기획(Phase 1~6 전체). `_workspace/`, `docs/planning/` 모두 존재하지 않아 신규 실행으로 진행.

## 인터뷰 질문 및 답변

1. **주요 타겟**: 경력직 이직자. 기존 경력을 체계적으로 정리하고 JD에 맞춰 어필 포인트를 찾는 사용자가 주 타겟.
2. **경력 데이터 입력 방식**: 수동 입력만. 이력서 업로드 파싱은 MVP 범위에서 제외(보류). 구조화된 폼으로 사용자가 직접 입력.
3. **AI 모의 면접 형식**: 실시간 대화형 채팅이 아니라, AI가 질문을 생성해 제시하고 사용자가 그 질문에 대한 답변을 텍스트로 입력하는 형식(턴 기반 입력, 실시간 음성/채팅 아님). 입력 완료 후 평가/피드백 제공.
4. **AI 출력 범위**: 인사이트·모의 면접을 넘어 자기소개서/경력기술서 초안 생성까지 포함.

## 확정 방향 요약

- 타겟: 경력직 이직자 (신입/커리어 전환자는 비타겟, 확장은 추후 검토)
- P1 입력: 수동 입력 전용 (이력서 업로드 파싱 보류)
- P3 모의 면접: 질문 생성 → 사용자가 텍스트 답변 입력 → AI 평가/피드백 (턴 기반, 비실시간)
- 출력 범위: JD 인사이트 + 모의 면접 + 자기소개서/경력기술서 초안 생성까지 MVP 범위에 포함

## PRD 수정 피드백 (2026-10-23, 사용자)

1. **커리어 정리와 이직 활동은 별개의 행동이다.** 연속된 단일 경로일 필요가 없다.
   - **커리어 정리**: 경력·프로젝트를 기입해 본인 커리어를 정리하는 독립 태스크.
   - **이직용 프로젝트 생성**: 이직 활동 단위로 별도의 "프로젝트"를 만들고, 그 안에서 JD 기반 AI 자기소개서 확인, 인사이트 확인을 한다.
   - **면접 연습**: 커리어 정리와는 별개이며, 생성한 이직용 프로젝트에 속하는 행동이다.
   - 즉 각 행동은 독립적으로 진입 가능하며, 순서를 강제하지 않는다.
2. **자기소개서 작성은 커리어 정리 데이터를 가져다 쓴다.**
   - 자소서 작성 시 기본 문항으로 **지원 동기 / 직무 역량 / 입사 후 포부 및 성장 계획** 3개를 보여준다.
   - JD에 준비된 질문이 있으면 사용자가 문항을 직접 수정할 수 있다.
   - AI가 **문항별로 어떤 경력의 어떤 프로젝트를 근거로 쓸지 판단**해 작성해 나간다.
3. **모의 면접은 시작 전에 면접 유형을 먼저 선택한다.** 예: 직무 면접, 컬처핏 면접 등.
4. **모의 면접은 턴 방식이 아니다.**
   - 질문을 한 번에 전부 생성 → 사용자가 답변을 한 번에 전부 입력 → 제출하면 답변을 기반으로 **점수**를 매긴다.
   - 점수 산정 방식은 사용자가 추후 구체화한다(현 단계에서는 미정).

### 리더 해석·가정 (사용자가 별도 지시 없이 반영 요청, 2026-10-23)

- [가정] 이직 활동 단위의 이름은 용어집의 "프로젝트(업무 단위)"와 충돌하므로 **"지원 프로젝트"**(가칭)로 부른다. 지원 프로젝트 1개 = 지원 대상 JD 1개 기준.
- [가정] 커리어 데이터가 부족한 상태에서 지원 프로젝트를 만들 수 있다. 인사이트·자소서는 최소 데이터 미달 시 커리어 정리로 안내하고, 면접 연습도 같은 기준을 적용할지는 [결정 필요].
- [가정] 자소서: AI가 문항별로 고른 경력·프로젝트를 문항 옆에 "사용한 경력·프로젝트"로 표시하고, 재생성 시 사용자가 변경 가능. 문항별 글자 수 제한은 유지.
- [가정] 면접 유형 MVP는 **직무 / 컬처핏(인성)** 2종, 그 외(임원 면접 등)는 [보류].
- 꼬리 질문(F-P3-05)은 일괄 방식과 맞지 않아 [보류].
- 기존 D-05 "총점 없음" 방침은 폐기. 면접 결과는 **점수**로 제공하며 산정 방식은 [결정 필요](사용자가 추후 구체화). 저장 구조와 결과 화면에 점수 자리만 마련한다.

## 추가 수정 피드백 2차 (2026-10-23, 사용자 원문 요약)

1. **홈은 대시보드 형식, 왼쪽 메뉴 구성**
   1. 커리어: 기존 커리어 관리. 홈 화면 디폴트 페이지.
   2. 기업 JD 관리: JD를 입력해 AI 자기소개서 작성 및 인사이트 확인(기존 내용과 동일 — 기존 "지원 프로젝트").
   3. 모의 면접: 기존 내용과 동일.
   4. 지원 현황: 보드(칸반) 형식. 컬럼 = 지원 전 / 서류 전형 / 과제 전형 / 직무 인터뷰 전형 / 컬처핏 전형 / 전형 종료(최종 합격, 불합격). 2번의 프로젝트(지원 프로젝트) 카드를 드래그앤드롭으로 이동. 인터뷰 전형으로 옮기면 팝업 → 면접 준비 페이지로 즉시 이동.
2. **커리어 관리 디테일**
   1. 계층: 연도 > 경력/교육 > 프로젝트 > 상세 내용.
   2. 상세 내용은 STAR(Situation / Task / Action / Result) 기법 기반으로 작성. 추가로 Insights를 작성할 수 있게.
   3. 프로젝트는 AI와 채팅으로 함께 작성할 수 있다.

### 리더 해석·가정 (2차)

- [가정] 사용자는 "메뉴 3개"라 했지만 4개 항목을 나열했으므로 왼쪽 메뉴는 **커리어 / 기업 JD 관리 / 모의 면접 / 지원 현황 4개**로 본다. 모의 면접 세션은 여전히 지원 프로젝트(= 기업 JD 관리의 항목)에 속하고, 모의 면접 메뉴는 전체 세션을 모아 보고 지원 프로젝트를 골라 시작하는 진입점이다.
- [가정] "기업 JD 관리"의 단위 = 기존 "지원 프로젝트". 화면상 메뉴명은 "기업 JD 관리", 개체 용어는 "지원 프로젝트" 유지 여부는 product-planner가 정리.
- [가정] 지원 현황 보드에서 직무 인터뷰 전형으로 이동 → 면접 유형 `job` 미리 선택, 컬처핏 전형 → `culture_fit` 미리 선택한 면접 준비 페이지로 이동(팝업에서 확인 후 이동, 취소 가능).
- [가정] "연도"는 별도 입력 개체가 아니라 기간 기준 그룹핑(보기 계층). "교육"은 새 개체(학교·교육기관, 기간, 전공/과정).
- [결정 필요] 상세 내용의 "Insights"는 기존 용어 "인사이트(JD × 사용자 데이터 분석 결과)"와 충돌한다. 사용자가 프로젝트에서 얻은 배운 점·회고를 뜻하는 것으로 보고, 다른 이름(예: "배운 점", "회고")을 제안한다.
- 프로젝트 AI 채팅 작성은 기존 "수동 입력만" 방침을 바꾼다. 이력서 업로드 파싱은 계속 [보류]. AI는 사용자의 답변만으로 STAR를 정리하며 경험을 지어내지 않는다.
