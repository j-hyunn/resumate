# 기획 정합성 리뷰

핵심은 **경계면 교차 비교**다. 한 문서 안의 완성도보다 문서 사이의 연결을 본다. 비교할 두 문서를 같이 열고, 한쪽의 각 항목이 다른 쪽에 존재하는지·같은 뜻인지 확인한다.

## 경계면 체크리스트

산출물이 나오는 대로, 비교 가능해진 경계면부터 검토한다.

| # | 경계면 | 확인 방법 | 가능 시점 |
|---|--------|----------|----------|
| B1 | PRD Must 기능 → 화면 | UX 매트릭스에 모든 Must 기능 ID가 있는가 | PRD + UX |
| B2 | 화면 필드 → 데이터 모델 | 화면 명세의 모든 `entity.field`가 테이블 정의에 있는가, 타입이 화면 용도와 맞는가 | UX + 데이터 |
| B3 | AI 입력 → 데이터 모델 | AI 카드 입력 컨텍스트의 모든 `entity.field`가 존재하는가 | AI + 데이터 |
| B4 | AI 출력 → 저장 | 출력 스키마가 저장될 테이블/jsonb가 정의되어 있는가, `schema_version` 있는가 | AI + 데이터 |
| B5 | AI 출력 → 화면 | 출력 스키마 필드(특히 evidence)를 표시하는 화면 요소가 있는가 | AI + UX |
| B6 | AI 응답 방식 일치 | AI 카드의 스트리밍/비동기와 화면 명세의 응답 방식이 같은가 | AI + UX |
| B7 | 기능 → 데이터 | 데이터 모델 매트릭스에 모든 Must 기능이 있는가 | PRD + 데이터 |
| B8 | 용어 | 같은 개념이 문서마다 다른 이름으로 쓰이지 않는가 (용어집 기준) | 전부 |
| B9 | MVP 범위 | PRD에서 [보류]인 기능이 다른 문서에서 MVP로 설계되지 않았는가, 그 반대는 없는가 | 전부 |
| B10 | 개인정보·삭제 | PRD 개인정보 요구사항이 데이터 모델 RLS·삭제 정책에 반영되었는가 | PRD + 데이터 |
| B11 | 비용 | AI 비용 추정 합이 PRD 사용자당 비용 상한 안인가 | PRD + AI |

## 심각도

- **Critical** — 구현 불가 또는 보안 문제 (필드 없음, RLS 누락, Must 기능 화면 없음)
- **Major** — 구현은 되지만 재작업 유발 (이름 불일치, 응답 방식 불일치, 범위 모순)
- **Minor** — 명확성 문제 (모호한 수용 기준, 누락된 엣지 상태)

## 리뷰 보고서 템플릿

```markdown
# Resumate 기획 정합성 리뷰 (라운드 {N})

## 요약
- 검토 문서: (버전 포함)
- 이슈: Critical N / Major N / Minor N, 해결 N / 미해결 N

## 경계면별 결과
| 경계면 | 결과 | 이슈 ID |

## 이슈 목록
### R-{번호} [{심각도}] {제목}
- 경계면: B2
- 근거: `02_ux-planner_flows.md` S-07 "experiences.role_title" ↔ `02_data-architect_data-model.md` experiences 테이블에 해당 컬럼 없음 (`title`만 존재)
- 담당: data-architect 또는 ux-planner
- 수정 제안:
- 상태: 열림 / 수정됨(확인 완료) / 미해결

## 통합 결정 필요 목록
(모든 문서의 [결정 필요]를 모아 중복 제거, 출처 문서 표기)
```

## 원칙

- 담당자를 하나로 지정한다. 양쪽 다 고칠 수 있으면 "기준 문서" 쪽(필드명은 데이터 모델, 범위는 PRD)을 기준으로 삼고 반대쪽을 담당자로 한다.
- 수정 라운드는 최대 2회. 남은 것은 미해결로 넘긴다.
- 직접 문서를 고치지 않는다.
