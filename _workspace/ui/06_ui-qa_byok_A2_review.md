## 참고 — 확인했고 문제없던 항목

- **S-08:** 시작 줄 순서가 명세 표 순서(+ 경력 / + 교육 / + 프로젝트 / AI)와 같다. AI 버튼은 default 버튼 + C-19 배지, 키 없음이면 C-18 인라인(대안 S-10)이다. 빈 상태의 기본 시작점은 "직접 입력"(+ 경력 / + 교육)이고, 트리 행 잠금 버튼은 FL-19 복귀 대상을 기억한다.
- **S-36 키 무효 처리:** 보내기·빠른 응답·단계 버튼·다시 보내기가 서버에 보내지 않고 C-20 `key_invalid` inline을 보이며, 입력은 유지된다(`chat-screen.tsx:160-166, 200-204`). 입력을 고치면 안내가 사라진다.
- **S-36 키 없음 처리:**
  - 열람·편집: 대화 기록, 정리 결과 직접 수정, C-15 수락·거절, 소속 변경, 저장, 폼 전환은 키 없이 된다(D-36).
  - 비활성: 보내기·빠른 응답·단계 버튼.
  - 입력: 입력창은 비활성이 아니라서 쓰던 글이 남는다.
- **C-20:** 실패 턴이 `AiErrorNotice size="inline"`에 `retryLabel="다시 보내기"`, `reduceTarget="답변"`(input_too_long → 입력으로 포커스)을 쓴다. `canceled`는 "중단했어요 · 다시 보내기"다. 게이트 대화의 첫 턴이 실패하면 "AI 대화 대신 직접 입력으로 채울 수도 있어요 [직접 입력하기]"(경력·보강 대상 반영)가 나온다.
- **무료 등급·대기 줄:** 시작 화면 "무료 등급은 응답이 조금 느릴 수 있어요", 정리 중 "정리 중 · 무료 등급이라 하나씩 처리해요", 대기 줄 문구·아이콘(`Hourglass text-ai`, 오류색 아님)이 DS 3.3과 같다.
- **40개 상한:** v5 문구 + 버튼 3개이고, "한도"라는 말은 쓰지 않는다. `n / 40` 표시와 36 이상 경고색도 유지된다.
- **C-09 / C-10:** `GateNextStep`이 키 없음(서버 `next_action = form` → `continueHref = null`)과 키 무효(클라이언트 판정) 모두에서 "직접 입력하기"를 주 버튼으로 둔다. 무효면 C-20 한 줄 + "키를 확인하면 AI와 대화로 채울 수 있어요 [AI 연결 확인]"(FL-19 복귀 대상 기억)이 붙는다. S-36 안의 C-10 배너는 계속 "AI와 대화하며 채우기"를 숨긴다(UQ-24).
