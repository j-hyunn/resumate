# R8 STAR 합친 제안 · -음 체 · 민감정보 판정 완화

- 날짜: 2026-11-04 · 선행: R7(같은 작업 트리, 미커밋)
- 계기: R7 로컬 확인 후 사용자 피드백 3건
- 사용자 확정 (2026-11-04):
  - **RQ-4 -음 체**: 프로젝트 STAR 제안 문장과 산출물 본문 초안은 "-음" 체("캐시 무효화 규칙을 설계함", "배포 시간이 40분에서 10분으로 줄었음"). AI 채팅 질문은 존댓말 그대로.
  - **RQ-5 합친 제안(전체 교체)**: 값이 있는 STAR 항목에도 "기존 내용 + 새 내용"을 합쳐 다시 쓴 **전체 문장**을 제안하고, [반영]은 그 항목을 교체한다. 사용자가 직접 쓴 문장도 합치면서 다시 쓴다. 기존 문장의 사실은 빠뜨리지 않는다.
  - **RQ-6 민감정보 = 본인 신상만**: 업무 도메인 단어(병원·입원·수술·출산·병가·교회·파업·선거 …)만으로는 걸지 않는다. 본인(또는 가족) 신상 맥락, 연락처, 실제 사람 이름 + 직함만 막는다. 직함 오탐("기획자 선배", "사업부 부장")을 고친다. 걸려도 발화 통째가 아니라 그 값만 뺀다.

## 현재 동작 (진단)

- AI-12 extract: 값이 있는 필드는 `append`만, "기존 문장을 고치거나 다시 쓰지 않습니다". V-9h가 값 있는 필드의 `set`을 거부. RPC `apply_structured_draft_patch`(20261109101000)는 op를 컬럼 상태로 강제(채워짐 → append)하고 미반영 제안에 append를 이어 붙인다. 화면 `src/components/career/star-proposal-fill.ts:122`는 폼 값이 있으면 `${current}\n${add}`로 이어 붙인다.
- 문체: 프롬프트 예시가 "~했다". `KOREAN_SUFFIXES`(v9-lexicon.ts)에 함·음·됨이 없어 -음 체로 바꾸면 V-9e(내용어 대조)에서 "설계함"이 "설계했어요"와 안 맞아 검토 필요가 급증한다.
- 민감정보: `SENSITIVE_PATTERNS`·`THIRD_PARTY_NAME_PATTERN`(v9-lexicon.ts) 단어 정규식. 실측: "병원 예약 시스템을 개발했어요"·"입원 환자 조회 화면"·"수술 일정 관리"·"출산 휴가 신청 기능"·"병가 처리 HR 기능" → health, "교회 출석 앱 외주" → religion, "파업 대응 공지 시스템" → union, "기획자 선배가"·"사업부 부장님께" → third_party_name. V-9g/V-10f는 값 **또는 인용(quote)**에 걸리면 그 주장을 버리고, 턴의 `sensitiveNotice`는 발화 전체에 걸면 "민감한 정보로 보여 기록하지 않을게요"를 띄운다.

## 설계 (팀 공통 계약)

### A. STAR 합친 제안 (AI-12)
- extract: 값이 있는 필드(폼 값 또는 아직 폼에 없는 제안)에 새 내용이 나오면 op **"set"**, value = 기존 텍스트(폼 값 + 미반영 제안) + 새 내용을 합쳐 자연스럽게 다시 쓴 전체 문장. 기존 문장의 사실(수치·고유명사·행동)은 모두 남긴다. 값이 비어 있으면 지금처럼 "set". **"append"는 더 이상 내지 않는다**(스키마·DB·화면은 과거 초안 호환 위해 계속 받음).
- source_message_ids·source_quotes는 이번에 새로 들어간 내용의 출처(user 발화)만.
- V-9 (값 있는 필드의 set = "merge"):
  - V-9h: 값 있는 필드의 `set` 허용(합친 제안). 기간 규칙은 그대로.
  - V-9c(숫자)·V-9d(이름)·V-9e(내용어): 출처 = 인용 + **그 필드의 기존 텍스트**(폼 값 + 미반영 제안 값).
  - 보존 검사(신규 V-9j): 기존 텍스트의 숫자(단위 포함)와 V-9d 이름이 합친 값에 모두 있어야 한다. 빠지면 `needs_review`.
  - 합친 값 == 기존 텍스트(정규화)면 unchanged. 길이: 합친 값 ≤ 2,000자(append 길이 계산 대신 교체 길이).
- RPC: 값 있는 필드에도 AI 패치 `set` 허용(제안 교체, `new_object` 규칙 유지). `append` 처리는 호환용으로 남긴다. 사용자 경로(user_edit)의 op 강제는 그대로 두되, 합친 제안 교체와 충돌하지 않게 한다.
- 화면 [반영]: 제안 op가 `set`이면 폼 항목을 **교체**(next = 제안 값, prev 보관 → 되돌리기), `append`(과거 초안)만 이어 붙임. 2,000자 검사도 교체 길이. 카드 라벨 "덧붙임" → "기존 내용과 합친 제안", 카드에서 기존 값과 비교해 볼 수 있게 한다.
- reply(AI-12): "이미 있는 글을 다시 써 달라고 하면 덧붙이는 것만…" 안내를 "합쳐서 다시 정리한 제안을 드릴 수 있다"로. 렌더러의 "덧붙임/새로 채움" 라벨 → "합친 제안/새로 채움".

### B. -음 체
- AI-12 extract STAR 값, AI-13 extract facts 문장, AI-13 compose 본문 블록(제목 제외): 문장 끝을 "-음/-함/-됨/-임"으로. 예시·경계 사례도 모두 -음 체로.
- `KOREAN_SUFFIXES`에 -음 체 어미 추가(긴 것 먼저): 하였음, 했었음, 했음, 되었음, 됐음, 었음, 였음, 았음, 함, 됨, 음, 임(남는 줄기 ≥ 2자 규칙 유지). V-10 내용어 대조도 같은 목록을 쓰는지 확인.

### C. 민감정보 판정 (V-9g, V-10f, sensitiveNotice)
- 연락처: 그대로.
- 건강·종교·노조·정치: **본인·가족 신상 맥락**만. 같은 문장 안에 1인칭/가족 표지(제가, 저는, 저도, 제, 본인, 개인적으로, 가족, 아내, 남편, 부모님, 아이 …)와 신상 서술(진단을 받, 투병, 입원했, 수술을 받, 병가를 냈/썼, 치료를 받, 임신했, 출산했, 육아휴직, 휴직, 우울증·공황 등 질환명 + 겪/앓, 다니는 교회·성당·절, 신앙, 신자, 조합원, 노조 활동, 파업에 참여, 지지 정당, 당원, 정치 성향)이 함께 있을 때. 도메인 단어만 있는 문장(병원 예약 시스템, 출산 휴가 신청 기능, 교회 출석 앱, 파업 대응 공지)은 걸지 않는다.
- 제3자 실명: 성씨+2자(+복성) + 직함 유지하되, 직무·조직 명사 오탐 제외(끝 글자가 자·부·사·팀·실·소·단·국·과·처·원으로 끝나는 기획자·사업부·고객사·협력사·연구소 … 와 마케팅·디자인 등 목록). [가정]
- 범위: **값(value / fact text / block text)에만** 적용. 인용(quote)에만 있고 값에 없으면 통과(값에 옮기지 않았으므로). 턴 안내(sensitiveNotice)는 새 판정으로 발화에 걸렸을 때만.
- 픽스처로 위 실측 문장 13개를 회귀 테스트로 둔다(오탐 0, "제가 우울증 진단을 받아서", "김민수 팀장님", 전화번호는 걸림).
