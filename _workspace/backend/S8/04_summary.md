## 만든 것
- **DB** (마이그레이션 `20261103000100`~`0700`)
  - 테이블: `interview_sessions`(v4.1 공급자 4컬럼), `interview_questions`, `interview_answers`, `answer_evaluations`, `session_feedbacks`
  - 지원 프로젝트당 작성 중 세션은 1개다.
  - 질문의 `intent`·`good_answer_signals`는 사용자에게 grant하지 않는다. `intent`는 제출 후 definer RPC로만 공개한다.
  - 답변은 다음 조건을 모두 만족할 때만 고칠 수 있다(RLS).
    - 작성 중인 답변이다.
    - 세션이 작성 중이고 아직 제출하지 않았다.
    - 질문 생성이 끝났다.
  - 사용자 RPC: 세션 생성, 그만두기, 결과 열람 표시, 제출, 제출 후 의도 공개
    - 제출: 빈 답변은 미응답으로 처리한다. 응답이 0개면 바로 완료로 둔다.

  - S5 보드 팝업에 작성 중 세션 정보를 채웠다.
  - 커리어 삭제 영향에 면접 세션을 포함했다. `delete_results`는 해당 세션을 삭제한다.
  - 세션을 삭제하면 진행 중 작업에 취소를 요청한다.
- **AI** (`ai-05.generate.v1`, `ai-06.evaluate.v1`, `ai-07.summarize.v1`)
  - AI-05: 질문을 스트리밍으로 받아 하나씩 저장한다.
    - 질문마다 검증한다: 금지 주제, 숫자 날조, 직무 질문의 회고 전제, 앵커 근거, 컬처핏 사실 가정, 중복.
    - 위반한 질문은 버리고, 남은 개수를 한 번 다시 만든다.
    - 비어 있는 번호를 오름차순으로 채운다.
  - AI-06: 답변별 평가를 3단계로 나눴다. 각 단계는 공급자 호출을 최대 1회 한다.
    1. 첫 평가
    2. 개선 답변 예시의 숫자 위반이 있을 때만 다시 생성
    3. 확정
    - 기준 4개 항목이 모두 있어야 한다.
    - 인용은 실제 답변의 부분 문자열이어야 한다.
    - 개선 답변 예시는 답변과 경력 데이터에 있는 사실만 쓴다. 그 밖의 내용은 "사실이라면 넣어 보세요" 제안으로 분리한다.
    - 점수는 항상 "준비 중"(`pending_method`)이다.
  - AI-07: 이 세션의 질문만 참조할 수 있다. 미응답 질문의 내용은 언급하지 않는다. 등급 분포는 서버가 계산한다.
- **API**
  - 질문 생성 작업: `prepare`(필요하면 JD 추출을 먼저 실행) → `generate` → `complete`
    - 질문을 하나 저장할 때마다 진행 상태를 갱신한다.
    - 모자란 질문은 한 번 다시 만든다.
  - 채점 작업: `prepare` → `evaluate` → `summarize` → `score` → `complete`
    - 유료 등급: 답변을 병렬로 채점하고, 끝나는 대로 저장한다.
    - 무료 등급: 실행 1번에 호출 1번, 6초 간격이다.
    - 답변 일부가 실패하면 그 답변만 `not_scored`로 둔다.
  - 라우트: 세션 시작, 남은 질문 다시 만들기, 제출, 다시 채점
  - 키 없이 쓸 수 있는 액션: 답변 자동 저장, 그만두기, 삭제, 결과 열람 표시
  - 조회
    - 면접 준비(S-20), 답변지(S-33), 결과(S-22, C-17 점수 표시), 전체 세션(S-37: 필터, 실행 공급자 표시 규칙)
    - 생성 중·채점 중으로 남은 행이라도 그 작업이 이미 끝났으면 실패로 보여 준다.
  - 목록·보드·허브에 면접 진행 표시를 채웠다.
  - 실행기에 `StepContext.wouldRetry`를 추가했다. 기존 작업 유형에는 영향이 없다.

## 사용자 확인이 필요한 `[가정]`
1. 종합 피드백만 실패하면 세션을 `evaluation_failed`로 둔다. 다시 채점하면 종합만 다시 만든다.
2. 답변 일부만 실패하면 세션은 완료로 두고, 그 답변만 "채점 실패 + 다시 채점"으로 보인다. 키·계정·공급자 한도가 원인이면 채점 전체를 실패로 둔다.
3. 질문 하나가 규칙을 어기면 그 질문만 버리고 남은 개수를 다시 만든다. 세트 구성 규칙은 질문 단위로 검사한다(스트리밍으로 저장하기 때문).
4. 그만둔 세션을 포함해 세션을 하나씩 삭제할 수 있다. 그만둔 세션의 답변은 편집할 수 없다.
5. 지원 프로젝트당 작성 중 세션은 1개다. 새로 시작하면 409와 함께 "이어 쓰기" 안내를 준다.
6. 질문 문장에 근거 없는 숫자가 있으면 `[수치 확인 필요]`로 바꾸지 않고, 그 질문을 버린 뒤 다시 만든다.
7. 개선 답변 예시를 다시 만드는 호출이 끝내 실패하면, 첫 평가에 `[수치 확인 필요]` 표시를 붙여 저장한다(`not_scored`로 두지 않는다).
8. "남은 질문 다시 만들기"와 "다시 채점"은 새 작업으로 시작한다.
