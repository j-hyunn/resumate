# AI 설계 결정 가이드

설계 카드를 쓰다가 판단이 갈릴 때 읽는다.

## 1. 컨텍스트 주입 vs RAG

| 상황 | 선택 |
|------|------|
| 한 사용자의 전체 경력·프로젝트가 수만 토큰 이하 | **전체 주입**. 검색 누락 위험이 없고 구현이 단순하다. 대부분의 개인 커리어 데이터는 여기 해당 |
| 첨부 문서(포트폴리오, 긴 경력기술서)가 쌓여 수십만 토큰 이상 | 요약 계층(항목별 요약 저장) 먼저 검토, 그래도 크면 pgvector 검색 |
| 여러 사용자/공개 데이터 검색(예: 직무별 면접 질문 은행) | RAG 적합 |

결론을 카드에 "왜 이 방식인가"와 함께 적는다. RAG를 택하면 data-architect에게 임베딩 저장 구조를 요청한다.

## 2. 단일 호출 vs 체인

- 단계마다 결과를 저장·재사용하거나 사용자 확인을 끼워야 하면 체인으로 나눈다. 예: JD 구조화 → (저장) → 매칭 분석 → 지원 방향.
- 한 번에 끝나는 생성(질문 1개, 피드백 1건)은 단일 호출.
- 단계를 나누면 중간 결과가 근거로 남아 디버깅·평가가 쉬워진다.

## 3. 모델 선택

| 작업 | 기본 |
|------|------|
| 파싱·분류·짧은 추출 | claude-haiku-5-5 |
| 인사이트·채팅·질문 생성·피드백 | claude-sonnet-5-5 |
| 종합 리포트처럼 깊은 추론이 필요하고 호출 빈도가 낮은 것 | claude-opus-5-5 검토 |

호출 빈도 × 단가로 사용자당 비용을 계산해 PRD 상한과 비교한다. 정확한 단가는 구현 단계에서 `claude-api` 스킬로 확인한다는 메모를 남긴다.

## 4. 구조화 출력

화면에 렌더링하거나 저장하는 출력은 JSON 스키마(tool use 기반 구조화 출력)로 받는다. 스키마에는 `schema_version`을 두어, 나중에 스키마가 바뀌어도 과거 결과를 읽을 수 있게 한다.

## 5. 가드레일 체크리스트

- **환각**: 사용자 데이터에 없는 경력·수치 생성 금지 지시 + `evidence` 필수화 + 근거 없는 항목은 "확인 필요"로 출력
- **프롬프트 인젝션**: JD·이력서는 외부 텍스트다. 그 안의 지시문을 따르지 않도록 사용자 데이터와 지시를 구분해 주입
- **개인정보**: 로그에 원문 저장 범위, 제3자(면접관 이름 등) 정보 처리
- **톤**: 피드백은 구체적·실행 가능하게, 인신공격성 표현 금지
- **실패**: 타임아웃·스키마 불일치 시 재시도 1회 → 사용자에게 재시도 버튼

## 6. 모의 면접 설계 요소

- 질문 소스: JD 필수 요건, 사용자 프로젝트(검증 질문), 직무 일반 질문, 인성 질문 — 비율을 정한다
- 꼬리질문: 답변이 모호하거나 수치·역할이 빠졌을 때. 최대 깊이를 정한다
- 평가 루브릭 예: 구조(STAR), 구체성(수치·역할), 직무 연관성, 전달력 — 항목별 점수 + 근거 인용 + 개선 예시
- 형식: 텍스트 MVP 후 음성 확장이 일반적. 음성은 STT/TTS 비용·지연이 추가되므로 `[결정 필요]`로 장단점 제시
- 세션 리포트: 질문별 피드백 + 종합 강점/개선점 + 다음 연습 추천
