## 3. 확정된 결정

### 3.1 사용자 확정 (2026-10-24)

| # | 결정 |
|---|------|
| U-1 | 모의 면접 점수 산식은 사용자 정의 대기 (D-14 유지) |
| U-2 | 상세 내용의 회고 필드 이름은 **"회고 및 배운 점"**. 근거 칩 표시도 같은 이름 |
| U-3 | 전형 종료 결과는 최종 합격 / 불합격 |
| U-4 | 왼쪽 메뉴 4개: 커리어 / 기업 JD 관리 / 모의 면접 / 지원 현황 |
| U-5 | 커리어 데이터가 부족하면 그 자리에서 **AI 작성 대화로 부족한 데이터를 채운 뒤 원래 기능으로 복귀**. 완료된 경력이 없으면 경력 폼을 먼저 연 다음 AI 대화로 넘어감. AI 결과는 저장된 근거 데이터로만 생성 |
| U-6 | 지원 프로젝트 1개 = JD 1개, JD 필수·교체 불가 |
| U-7 | MVP 면접 유형은 직무 / 컬처핏 2종 |
| U-8 | AI 작성 대화 월 한도 10회 |
| U-9 | 프로젝트에 연결된 AI 대화는 계속 보관, 대화만 따로 삭제 가능 |
| U-10 | PRD 권고 일괄 승인: D-02(JD 텍스트 입력만), D-04(커리어 채팅 Should), D-05(인사이트에 점수 없음), D-06(질문 수 3/5/7), D-09(매직 링크 + Google 로그인), D-10(출시 전 LLM 약관 확인), D-11(탈퇴 즉시 파기), D-17(사용량 단위), D-18(인사이트는 사용자가 시작) |

### 3.2 사용자 확정 (2026-10-23, 인터뷰와 수정 피드백)

| 결정 | 근거 |
|------|------|

| 이력서 업로드 파싱은 보류. 커리어 입력은 폼 + AI 채팅 작성 | 인터뷰, 2차 피드백 |
| 자기소개서·경력기술서 초안 생성을 MVP에 포함 | 인터뷰 |

### 3.3 팀 확정 (2026-10-23~24, 리뷰 권고 채택)

| # | 결정 |
|---|------|
| T-1 | 문서·데이터 용어는 "지원 프로젝트", 메뉴는 "기업 JD 관리", 화면 표기는 "기업 JD", JD 원문은 "공고 원문" |
| T-2 | 연도 보기: 경력·교육은 활동한 모든 연도에, 프로젝트는 시작 연도에 표시. 기간 정보가 없으면 "연도 미정" |
| T-3 | 프로젝트 1개에 상세 내용 여러 개 |
| T-4 | STAR의 결과 = 서술 + 정량 성과 0개 이상 |
| T-5 | 보드 열 안에서는 최근 이동순 |
| T-6 | AI 대화에서 폼으로 전환하면 작성 중(draft) 항목으로 저장 |
| T-7 | 전형 종료에서 다른 열로 옮기면 결과를 지우고, 이전 결과는 이력에 보존 |
| T-8 | 좁은 화면의 보드는 열 탭 + 카드 메뉴로 이동 |
| T-9 | 답변란은 질문이 모두 생성된 뒤 열림 |
| T-10 | AI 작성 대화는 첫 응답이 성공하면 1회 차감. 보강 대화와 게이트 진입 대화도 1회. 한도에 도달하면 새 대화만 차단 |
| T-11 | 회고 및 배운 점은 자소서의 포부·지원 동기·경험 서술 문항에서 회고 표현으로만 사용하고, 사실 근거로는 쓰지 않음 |
| T-12 | 인터뷰 팝업: 작성 중 세션이 있으면 이어 쓰기를 먼저 안내 |
| T-13 | Should 항목은 MVP에 최소 범위만 노출 |
| T-14 | 비동기 AI 작업은 `after()`로 시작 |
| T-15 | 답변 평가·대화 응답은 Sonnet으로 시작하고, 평가 세트를 통과하면 Haiku로 전환 |
| T-16 | 데이터 최소 기준(D-01): 완료된 프로젝트에는 완료된 상세 내용이 1개 이상 있어야 함. 교육만으로는 기준 미달 |
| T-17 | 민감정보가 걸러진 발화도 대화 원문에는 보관하고, 사용자에게 안내 |
| T-18 | 수락하지 않은 "검토 필요" 필드는 저장할 때도, 폼으로 전환할 때도 옮기지 않음 |
| T-19 | 확정 소속은 `writing_chats.experience_id` / `education_id`가 단일 원천 |
| T-20 | 게이트 진입 대화는 지원 프로젝트 요건을 질문 순서와 주제를 정하는 데만 쓰고, 근거로는 쓰지 않음 (R-31) |
