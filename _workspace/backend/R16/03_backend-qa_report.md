## A. 정규식 폭주(ReDoS)

### 방법
- 동기 정규식이 막히면 프로세스 안의 타이머로는 멈출 수 없다. 그래서 **사례마다 vitest 프로세스를 따로 띄우고 바깥에서 강제 종료**했다(프로세스 그룹 단위. 처음 실행에서 종료된 부모가 남긴 워커가 2분 넘게 CPU 99.7%로 돌던 것을 확인하고 고쳤다 — 그 자체가 정규식이 끝나지 않는다는 증거다).
- 입력은 모두 2 MB 바이트 상한 바로 아래(ASCII 1,990,000자)다.
- 원인 정규식은 **순수 Node에서 그 정규식만** 돌려 크기를 2배씩 키우며 쟀다. 2배마다 약 4배면 O(n²), 약 8배면 O(n³)다.
- **R15 비교**: `git show HEAD:…/fetch.ts`를 임시 모듈로 올려 **같은 입력을 R15 코드에** 넣었다.

### QA-R16-01 [Critical] 강조·제목 변환이 O(n²) — **R16 신규 회귀**

- 담당: **api-engineer** (`fetch.ts`)
- 원인 정규식(각각 단독으로 O(n²)를 확인):

  | 줄 | 정규식 | 50k | 100k | 200k | 2 MB 추정 |
  |----|--------|-----|------|------|-----------|
  | **277** | `/<(strong\|b)(?:\s[^>]*)?>([\s\S]*?)<\/\1\s*>/gi` | 104 ms | 418 ms | 1,662 ms | **≈ 166 s** |
  | **278** | `/<(em\|i)(?:\s[^>]*)?>([\s\S]*?)<\/\1\s*>/gi` | 104 ms | 419 ms | 1,696 ms | **≈ 170 s** |
  | **283** | `/<h([1-6])\b[^>]*>([\s\S]*?)<\/h\1\s*>/gi` | 85 ms | 341 ms | 1,398 ms | **≈ 140 s** |
  | 283 | 같은 정규식, 짝 안 맞는 `<h1>x</h2>` | 54 ms | 222 ms | 902 ms | ≈ 90 s |

- 이유: 닫히지 않은 여는 태그마다 `[\s\S]*?`가 **문자열 끝까지** 닫는 태그를 찾는다. 여는 태그가 n개면 n × n이다.
- 재현(`htmlToMarkdown`, 2 MB): `<b>`·`<strong>`·`<i>`·`<b>x`·`<h1>`·`<h1>x`·`<h1>x</h2>` 반복 → **7건 모두 20초에 강제 종료**. `htmlToMarkdown` 안에서 잰 100k 값(419 ms)이 단독 정규식 값(418 ms)과 같다.
- R15 같은 입력: **25 ms(`<b>`) · 28 ms(`<i>`) · 42 ms(`<h1>`)** → R16이 만든 회귀다.
- 수정 제안: 표·목록에서 이미 쓰는 **템퍼드 패턴**으로 바꾼다 — 예: `/<(strong|b)(?:\s[^>]*)?>((?:(?!<(?:strong|b)[\s>\/])[\s\S])*?)<\/\1\s*>/gi`. 그러면 탐색이 **다음 같은 여는 태그에서 멈추어** 전체가 선형이 된다. 고친 뒤 스크래치패드 하네스(아래)의 7건이 수백 ms 안에 끝나는지 확인할 것.
- 상태: **열림**

### QA-R16-02 [Critical] 태그·블록·JSON-LD·iframe 스캔 — **R15부터 있던 것, 운영 노출 중**

- 담당: **api-engineer** (`fetch.ts`)
- 원인 정규식(각각 단독 측정):

  | 줄 | 정규식(요지) | 막는 입력 | 증가 | 측정 | 2 MB 추정 |
  |----|--------------|-----------|------|------|-----------|
  | **255** | `/<[^>]*>/g`(stripTags) | `<` 반복 | O(n²) | 25k 220 ms · 50k 743 · 100k 3,023 | **≈ 20분** |
  | **415** | `/<!--[\s\S]*?-->/g` | `<!--` 반복 | O(n²) | 100k 427 ms | ≈ 3분 |
  | **416** | `/<img\b[^>]*>/gi` | `<img ` 반복 | O(n²) | 100k 669 ms | ≈ 4분 |
  | **246** | `BLOCK_TAGS` `…\b[^>]*>` | `<div ` 반복 | O(n²) | 100k 697 ms | ≈ 5분 |
  | **423** | `/<\/?(li\|tr\|td\|th\|table\|ul\|ol)\b[^>]*>/gi` | `<li ` 반복 | O(n²) | 100k 774 ms | ≈ 5분 |
  | **514** | JSON-LD `<script\b[^>]*type…[^>]*>([\s\S]*?)<\/script` | `<script ` 반복 | O(n²) | 200k 1,873 ms | ≈ 3분 |
  | 514 | 같은 정규식 | 닫지 않은 `<script type=ld+json>` 반복 | O(n²) | 200k 152 ms | ≈ 15초 |
  | **205** | 보일러플레이트 `open` `…\b[^>]*(?:class\|id)\s*=…[^>]*>` | `<div class="x" ` 반복 | **O(n³)** | 2k 5 ms · 4k 42 · 8k 320 | **수 주(사실상 무한)** |
  | **547** | iframe `…\b[^>]*\bsrc\s*=…[^>]*>` | `<iframe src="` 반복 | **O(n³)** | 2k 8 ms · 4k 62 · 8k 418 | **수 주(사실상 무한)** |

- O(n³)인 이유: `[^>]*` 뒤에 `(?:class|id)`가 오고, 그 뒤에 또 `[^>]*>`가 있다. 그래서 여는 태그마다 **뒤의 모든 `class` 위치를 하나씩 다시 시도**하고, 시도마다 끝까지 `>`를 찾는다.
- 재현(2 MB, 15초 강제 종료): `htmlToMarkdown` — `<`·`<div `·`<div class="x" `·`<!--`·`<img ` 5건, `extractJobPosting` — 2건, `bodyFrameUrl` — 1건, **모두 막힘**. **R15 코드에서도 8건 모두 막힘**(같은 하네스).
- 왜 지금 Critical인가: R15는 운영에 나가 있다. **R16을 머지하지 않아도 운영 엔드포인트가 지금 이 입력에 막힌다.** R16 머지 여부와 별개로 처리해야 한다.
- 수정 제안:
  1. `[^>]*`를 **`[^<>]*`**로 바꾼다(255·205·246·416·423·514·547). 그러면 탐색이 **다음 `<`에서 멈추어** 선형이 된다. 정상 HTML의 태그 안에는 날것의 `<`가 없으므로 결과가 바뀌지 않는다.
  2. `<!--[\s\S]*?-->`·`<script…>([\s\S]*?)</script>`는 `indexOf`로 닫는 쪽을 **한 번만** 찾는다. 닫는 쪽이 없으면 문자열 끝까지 버린다.
  3. **다음 회귀 방지**: CPU 단계에 실제 상한을 둔다 — 변환에 넣는 HTML 길이를 전처리 뒤 상한(예: 500 KB)으로 자르거나, 변환을 워커 스레드에 넣고 시간 제한을 건다. 지금은 10초 deadline이 네트워크 단계에만 걸린다.
- 상태: **열림**

## B. 자리 표시 토큰 주입

토큰은 `\u0000TABLE{n}\u0000`(`fetch.ts:251-252`), 되돌리기는 `tables[n] ?? ""`(`fetch.ts:430`)다. 근거: 스크래치패드 `token.out`.

| 입력 | 결과 |
|------|------|
| 본문의 `&#0;TABLE0&#0;` / `&#x0;TABLE0&#x0;` | **글자 그대로 남는다** — `decodeEntities`가 코드 포인트 0을 디코드하지 않는다(`code <= 0` → 원문, `fetch.ts:171`). 엔티티 경로는 막혀 있다 |
| 범위 밖 `\u0000TABLE7\u0000` / 아주 큰 번호 | 조용히 지워진다. **터지지 않는다**(`?? ""`) |
| **날것 NUL 바이트로 쓴 `\u0000TABLE0\u0000` + 진짜 표** | **진짜 표가 그 자리에 한 번 더 들어간다**(표 2벌) |
| 제목 안의 날것 토큰 | `## | 구분 | 내용 |` + 표 행 — **모양이 깨진 제목** |
| 셀 안의 날것 토큰 | 빈 셀 |
| 토큰 없는 NUL 바이트 | **`rawText`에 그대로 남는다** — 아래 QA-R16-04 |

판정: 공격자는 **자기 페이지의 출력만** 바꿀 수 있다(같은 응답 안에서 자기 표를 복제·이동). 남의 데이터·권한·이스케이프 우회로 이어지지 않는다. 되돌린 표는 이미 이스케이프된 그 표 자체다. → 보안 문제는 아니다. NUL 처리와 묶어 QA-R16-04(Minor)로 올렸다.

### QA-R16-04 [Minor] 날것 NUL 바이트 — 토큰 주입 + DB 저장 실패
