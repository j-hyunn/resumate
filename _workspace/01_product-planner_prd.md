## 1. 개요

### 1.1 한 줄 정의
경력직 이직자가 **커리어** 메뉴에 경력·교육·프로젝트를 STAR 구조로 쌓아 두고(직접 쓰거나 AI와 대화하며 작성), 지원하는 회사마다 **지원 프로젝트**를 만들어 근거 있는 인사이트, 경력기술서·자기소개서 초안, 모의 면접을 받는다. 각 지원의 진행 단계는 **지원 현황** 보드에서 관리한다.

### 1.2 해결하려는 문제
| # | 문제 | 설명 |
|---|------|------|
| PB-1 | 경력이 정리되어 있지 않다 | 3~10년 차 이직자는 경력이 여러 회사·프로젝트에 흩어져 있고, 성과 수치는 기억에 의존한다. 막상 정리하려 해도 무엇을 어떻게 써야 할지 막막하다. |
| PB-2 | JD마다 어필 포인트를 찾기 어렵다 | 같은 경력이라도 JD에 따라 강조할 부분이 다르다. |
| PB-3 | 서류 작성 반복 비용이 크다 | 지원처마다 경력기술서·자기소개서를 다시 고쳐 쓴다. 범용 AI 도구로 쓰면 없는 경험이 섞이거나 일반론이 나온다. |
| PB-4 | 경력직 면접 준비 수단이 부족하다 | 경력직 면접은 "그 프로젝트에서 본인이 정확히 뭘 했나"를 깊게 파고든다. |
| PB-5 | 지원 건별 준비물과 진행 상황이 흩어진다 | 여러 곳에 동시에 지원하면 JD, 분석, 자소서, 면접 준비, 전형 단계가 뒤섞인다. |

### 1.3 왜 지금, 왜 AI인가
- LLM이 비정형 JD를 구조화하고 사용자 데이터와 요건을 의미 단위로 대조하는 작업을 실용적인 비용으로 할 수 있다.
- LLM은 **인터뷰어처럼 질문을 던져 사용자의 기억을 STAR 구조로 끌어내는 일**에도 강하다. 그래서 수동 폼 입력의 부담을 줄일 수 있다(v3).
- Resumate는 커리어 데이터를 단일 근거(source of truth)로 두고, 모든 AI 출력을 그 데이터와 JD에 연결한다. AI는 사용자가 말하지 않은 사실을 만들지 않는다.

## 3. 제품 구조와 핵심 작업

### 3.1 내비게이션 (대시보드형 왼쪽 메뉴)

```
왼쪽 메뉴 (모든 화면 공통)
├── 커리어  ← 로그인 후 기본 첫 화면
│     연도 > 경력 / 교육 > 프로젝트 > 상세 내용 (STAR + 회고 및 배운 점)
│     프로젝트 작성: 직접 입력(폼) 또는 AI와 대화하며 작성
│
├── 기업 JD 관리  ← 지원 프로젝트 목록·생성·상세
│     지원 프로젝트 1개 = JD 1개 [가정]
│       ├── JD (원문 + 추출된 요건)
│       ├── 인사이트
│       ├── 서류: 경력기술서 / 자기소개서 초안
│       └── 모의 면접 세션 (이 지원 프로젝트에 속함)
│
├── 모의 면접  ← 모든 지원 프로젝트의 면접 세션 모아보기 + 새 면접 시작(지원 프로젝트 선택)
│
└── 지원 현황  ← 지원 프로젝트 카드 칸반 보드 (전형 단계 6열)
```

- **데이터 소속**: 모든 데이터는 커리어(사용자 1명당 1개) 또는 지원 프로젝트(여러 개) 중 한쪽에 속한다. "모의 면접" 메뉴와 "지원 현황" 메뉴는 지원 프로젝트의 데이터를 다르게 보여 주는 **보기이자 진입점**이다. 면접 세션은 항상 지원 프로젝트에 속하고, 전형 단계는 지원 프로젝트의 속성이다 [가정].
- **순서 없음** (v2 유지): 어느 메뉴도 다른 메뉴의 완료를 요구하지 않는다. 연결은 데이터뿐이다. 지원 프로젝트의 AI 기능은 커리어 데이터를 읽기 전용으로 쓰고, 데이터가 부족하면 커리어로 안내한다(F-AP-06).
- **첫 화면**: 로그인 후 항상 커리어로 간다 [가정: 마지막으로 본 메뉴를 기억하지 않는다]. 커리어가 비어 있으면 "AI와 대화하며 첫 프로젝트 정리하기"와 "직접 입력" 두 시작점을 보여 준다. 다른 메뉴로 가는 것은 막지 않는다.

MVP는 아래 6개 작업을 각각 처음부터 끝까지 할 수 있어야 한다.

| 작업 | 사용자 행동 | 시작 조건 | 관련 기능 |
|------|-------------|-----------|-----------|
| J-1 커리어 정리 | 경력·교육을 등록하고, 프로젝트와 상세 내용(STAR + 회고 및 배운 점)을 폼으로 쓰거나 AI와 대화해 쓴 뒤, 연도별 계층으로 본다 | 로그인 | F-P1-01~06, 09, 13~15 |
| J-2 지원 프로젝트 만들기 | 기업 JD 관리(또는 지원 현황 보드)에서 JD를 붙여넣어 지원 프로젝트를 만든다 | 로그인 | F-AP-01~03, 05, F-P2-01, 02 |
| J-3 인사이트 보기 | 지원 프로젝트에서 인사이트를 생성해 근거와 함께 본다 | J-2 + 데이터 최소 기준(D-01) | F-P2-04, 05, 09, F-AP-06 |
| J-4 서류 초안 만들기 | 경력기술서 또는 자소서 초안을 생성·편집·복사한다 | J-2 + D-01 | F-DOC-01~04, 08, 09 |
| J-5 모의 면접 | 지원 프로젝트를 고르고(또는 지원 현황 팝업으로 들어와) 면접 유형을 정한 뒤, 모든 답변을 작성해 한 번에 제출하고 점수를 받는다 | J-2 + D-15 | F-P3-01~04, 06, 07, 13, 15 |

## 4. 기능 요구사항

우선순위: MoSCoW. 기능 ID는 바꾸지 않고 폐기 ID는 재사용하지 않는다. v3에서 바뀐 행은 비고에 **(v3)**로 표시한다.

### P1. 커리어 (커리어 정리)

**계층** (v3): 연도 > 경력 / 교육 > 프로젝트 > 상세 내용.
- **연도**는 입력하는 개체가 아니라 기간으로 묶어 보여 주는 **보기 계층**이다 [가정]. 묶는 규칙은 D-22.
- 프로젝트는 경력, 교육 중 하나에 속하거나 어디에도 속하지 않는다(독립 프로젝트).
- 상세 내용은 프로젝트 아래 STAR 단위 기록이다. 한 프로젝트에 여러 개 둘 수 있다 [권고, D-23].

**입력 방식** (v3): 구조화된 폼 직접 입력 **또는** AI와 채팅하며 공동 작성. 이력서 파일 업로드 파싱은 계속 `[보류]`.

### 6.4 비용과 사용량
- `[가정]` 1인당 월 AI 비용 상한 US$2는 **평균 기준**. 출시 후 p90을 보고 한도를 조정한다(D-12).
- 무료 한도 예시 `[가정]` (달력 월, KST): 인사이트 10회, 초안 20회, 모의 면접 5세션, **AI 작성 대화 10회**(확정 2026-10-24 (사용자), U-8). 다른 한도 수치는 `[가정]`.
- 사용량 단위·차감 시점(D-17 v3):
  - 인사이트 생성 1회 = 1
  - 경력기술서 1건 / 자소서 문항 1개 = 초안 1
  - 면접 = 질문 생성에 성공했을 때 세션 1회(채점 포함). 재응시(F-P3-08)는 제출할 때 1회(D-AI-08 (a)). 남은 질문을 다시 만드는 것은 차감하지 않음(D-DM-07)
  - **AI 작성 대화 = 대화 1회당 1** (v3.1, 확정 2026-10-23, T-10/R-23): **첫 사용자 메시지에 대한 AI 응답이 성공했을 때** 1회 차감한다(시작 화면만 열고 나가면 무차감). 같은 대화를 이어 하면 다시 차감하지 않는다. 기존 프로젝트를 보강하는 대화도 대화마다 1회. 메시지 상한 40개 = **사용자 + AI 메시지 합계** [가정: 수치]. 상한 CHECK 제약 등 저장 규칙은 상한 수치 확정 후 data-architect가 정한다
  - 요건 추출, 보드 이동, F-ST-04 팝업, 채점 실패 후 다시 채점은 차감하지 않는다. 실패도 차감하지 않는다
- 한도에 닿으면 그 기능의 **새 실행만** 막고 열람·편집은 계속 허용한다. AI 작성 대화가 한도에 닿으면 새 대화만 막고, 진행 중인 대화의 이어 하기·저장·폼 전환은 허용한다.

2. **커리어 화면 재설계**(F-P1-09, 14, 15): 연도 > 경력/교육 > 프로젝트 > 상세 내용 계층 보기(연도 묶음 규칙 D-22 권고안 (b), 독립 프로젝트는 "기타 프로젝트"). 교육 입력 폼 신설. 프로젝트 폼에서 "기여 내용"을 빼고, 상세 내용(제목 + 상황/과제/행동/결과 + 회고 및 배운 점, 여러 개, D-23) 편집 화면을 만들어 주세요. 결과에는 정량 성과 첨부(D-24). "본인이 한 일" 가이드는 행동 필드로 옮기고, "팀·배경" 필드는 없앱니다(상황이 대신함).
3. **AI 작성 대화 화면 신설**(F-P1-13): 대화 영역 + 정리 결과 미리보기(필드별 출처 발화 연결), 필드 직접 수정, "저장" 확정, 중단 후 이어하기, 폼으로 전환(내용 채워진 상태). 시작점: 커리어 빈 상태, 프로젝트 상세, F-AP-06 데이터 부족 안내, F-P2-09 보완점 링크. 사용량 안내(대화 1회 차감, 메시지 상한).
4. **지원 현황 보드 신설**(F-ST-01~05): 고정 6열, 카드 내용, 드래그앤드롭 + 카드 메뉴 "단계 이동"(키보드·모바일), "지원 전" 열에서 바로 만들기, 전형 종료 결과 선택 창(최종 합격 / 불합격, 닫으면 결과 미기록), **직무 인터뷰 / 컬처핏 전형으로 옮길 때의 팝업**(확인 → 유형이 미리 선택된 면접 준비 화면, 취소 → 이동만 유지, 작성 중 세션이 있으면 그 세션으로 안내), 이동 실패 시 원위치.
5. **모의 면접 메뉴 화면 신설**(F-P3-15): 전체 세션 목록(지원 프로젝트·유형 필터, 작성 중 세션 맨 위), "새 면접" → 지원 프로젝트 선택 → 면접 준비 화면. 면접 준비 화면(F-P3-01)은 유형 미리 선택 진입을 지원해 주세요.
6. 기업 JD 관리 목록에 전형 단계 표시(F-AP-02), 삭제 확인에 전형 이력 포함(F-AP-05).
7. 화면 문구에서는 개체 이름 "지원 프로젝트"가 거의 드러나지 않게 하고(카드 제목 = 회사명 – 포지션명), 꼭 필요한 곳의 표기를 정해 주세요(D-20). 회고 필드 라벨은 "회고 및 배운 점"(D-21 권고, 확정 전).

### ai-feature-designer
1. **AI 작성 대화 기능 카드 신설**(F-P1-13): 질문 순서(기본 정보 → S → T → A → R(수치) → 회고 및 배운 점), 한 번에 1~2개 질문, 사용자 답을 프로젝트 필드·STAR 필드로 정리하는 출력 스키마, **필드마다 출처 발화 연결**, 발화에 없는 사실 금지(NFR-AI-02), 팀 성과/본인 기여 혼동 시 되묻기, 민감정보 감지 시 옮기지 않기(NFR-PRV-05), 메시지 상한 40, 모델 선택과 대화 1회 비용 추정. 평가 세트(대화 20건, 날조 0%)를 정의해 주세요.
2. 기존 F-P1-08(AI-08)은 "폼 STAR 필드 하나 다듬기"로 범위를 줄여 주세요(Should).
3. **경력 팩 입력 구조 변경**: 교육, 상세 내용(STAR 5필드), 상세 내용에 붙은 정량 성과를 포함하고, 근거 참조 단위를 STAR 필드까지 내려 주세요(예: 상세 내용 X의 행동). `contribution`·`team_context` 전제는 없앱니다. 회고 및 배운 점은 "본인의 회고"로 구분해 쓰고 사실 근거처럼 인용하지 않게 해 주세요(NFR-AI-06).
4. 인사이트·경력기술서·자소서·면접 질문의 프롬프트와 근거 규칙을 STAR 기준으로 다시 맞춰 주세요. 직무 면접은 행동·결과, 컬처핏은 상황·회고 및 배운 점을 활용합니다(F-P3-02). 자소서 "입사 후 포부 및 성장 계획"에서 회고 및 배운 점을 쓸 수 있습니다(F-DOC-09).
5. 데이터 최소 기준(D-01) 정의 변경: 완료 프로젝트 = 완료된 상세 내용이 1개 이상 있는 프로젝트. 교육 아래 프로젝트도 셉니다.
6. 비용 시나리오에 AI 작성 대화(월 한도 10회, 사용자 확정)를 더해 평균 US$2 기준을 다시 확인해 주세요. 점수 계산은 D-AI-07 (a)로 진행합니다(산식은 D-14 대기).

### data-architect
1. **교육 엔티티 신설**(F-P1-14): 기관명, 구분(학위 과정 / 교육 과정), 전공·과정명, 기간, 상태, 설명, `status`(draft/complete). 프로젝트의 소속을 경력 / 교육 / 없음 중 하나로 바꿔 주세요(둘 다 동시에는 불가).
2. **상세 내용 엔티티 신설**(F-P1-15): 프로젝트 1:N, 제목·상황·과제·행동·결과(서술)·회고 및 배운 점·순서·`status`. `projects.contribution`, `projects.team_context`는 상세 내용으로 옮기거나 없애 주세요. 프로젝트의 완료 판정은 "완료된 상세 내용 ≥ 1"을 포함합니다.
3. **성과 연결 변경**(D-24 (b)): 성과는 상세 내용 또는 경력 중 하나에 연결. 근거 참조(`evidence_links`)와 삭제 영향 조회가 상세 내용과 STAR 필드 단위를 다룰 수 있게 해 주세요.
4. **AI 작성 대화 저장**(F-P1-13, D-27 (a)): 프로젝트에 묶인 대화 스레드와 메시지, 저장 전 정리 결과(필드별 출처 메시지 참조), 이어하기 상태. 대화만 따로 삭제, 프로젝트 삭제·탈퇴 시 연쇄 삭제. 기존 `chat_threads`(커리어 채팅, Should)와 용도를 구분해 주세요.
5. **지원 현황**(F-ST-01~05): `application_projects`에 전형 단계(6값, 기본 "지원 전")와 전형 결과(최종 합격 / 불합격 / 미기록, D-25)를 두고, v2의 `application_status`(Could)는 이것으로 대체해 주세요. 전형 이동 기록 테이블(이전 단계, 새 단계, 시각)을 MVP부터 쌓고, 지원 프로젝트 삭제 시 함께 지워 주세요. 열 안 정렬은 최근 이동순(D-26 (a)).
6. **사용량**(D-17 v3): `writing_chat` 단위 추가(대화 시작 시 1회, 이어 하기는 무차감), 재응시는 제출 시 1회, 남은 질문 재생성은 무차감.
7. `get_data_readiness()`의 D-01 판정을 v3 정의(완료 상세 내용이 있는 완료 프로젝트, 교육 소속 포함, 교육만으로는 불충분)로 바꿔 주세요.

### v3.1 추가 요청 (리뷰 1차 확정 사항 전달)
- **ux-planner**: 커리어 화면 "작성 중인 AI 대화"에 자동 삭제까지 남은 기간 표시(NFR-PRV-06 `[가정]` 90일). 회고 근거 칩 라벨 "회고 및 배운 점". 화면에서 JD 원문은 "공고 원문". 민감정보 알림에 "대화 기록에는 남아 있어요" 문구(NFR-PRV-05). 세션 목록의 그만둠 세션은 아래쪽에 남기고 삭제 가능(F-P3-15).
- **ai-feature-designer**: AI 작성 대화 차감은 첫 사용자 메시지에 대한 응답 성공 시 1회, 상한 40 = 사용자 + AI 합계(6.4). 회고 및 배운 점의 자소서 사용 문항은 포부·지원 동기·경험 서술형(F-DOC-09). 근거 칩 표시명은 "회고 및 배운 점".
