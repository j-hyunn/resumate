### R-79 [Major] "종합 평가 다시 정리" 조건이 UX·AI와 DM에서 다르다

- 경계: B2, B5
- 근거: `02-user-flows.md` S-22 1284행 "세션 `evaluation_failed` + 실패한 답변 0개" ↔ `04-data-model.md` 2.7.1 525행 "대상 0, 평가 성공 ≥ 1, 종합 실패가 입력 원인 아님"
- 판단: DM 기준으로 맞춘다. UX 조건에는 문제가 둘 있다.
  1. **버튼이 잘못 뜬다.** 키·계정·한도 원인이면 답변을 닫지 않고 작업 전체가 실패한다(AI-06 1428행). 그러면 답변이 `pending`이라 "실패한 답변 0개"인데 평가 안 된 답변이 남아 있다. 이때 종합만 다시 만들면 답변 평가가 빠진다. DM 정의로는 다시 채점 대상이 1개 이상이라 "다시 채점"으로 간다.
  2. **막다른 길이 생긴다.** 입력 원인 답변이 섞이고 나머지는 성공, 종합은 공급자 원인으로 실패한 세션은 UX 어느 행에도 맞지 않는다.
- 담당: ux-planner
- 수정:
  - 1284행 조건: "세션 `evaluation_failed` + **다시 채점 대상 0개**(제출 답변 중 평가 성공이 없고 입력 원인도 아닌 답변, DM 2.7.1) + 평가 성공 1개 이상 + 종합 실패 원인이 입력 원인 아님". 입력 원인 답변이 섞인 경우는 `[가정]`으로 표시한다(Q53-5 문구를 넘는 확장이고, 답변 재호출이 없으므로 결정 취지와 맞는다). 이 경우 입력 원인 답변 카드는 원인만 보인다.
  - 1285행 `{n}`: "다른 원인 답변만" → "다시 채점 대상 수(`pending` 포함)". 1281행 버튼 조건 "입력 원인이 아닌 실패 답변이 있을 때"도 "다시 채점 대상이 있을 때"로 바꾼다.
  - FL-12 424행 라벨과 434행: "다시 채점 대상 없음 · 종합만 실패"로 바꾼다.
  - S-22 표 위나 아래에 DM 2.7.1 판정표(526~529행)를 가리키는 한 줄을 둔다. S-37 메뉴(1316행)도 같은 판정이라고 적는다.
- 상태: fixed (verified, 라운드 2)
