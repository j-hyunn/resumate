## 다른 팀원에게 요청

### ux-planner (`02-user-flows.md`)
1. **S-08 커리어**를 왼쪽 목록(연도 > 경력·교육·독립 프로젝트, 시작 연도에 한 번) + 오른쪽 상세 2단으로 다시 쓴다. 맨 위 "커리어 추가" 버튼 하나 → 경력 / 교육 / 프로젝트(독립) 선택(F-P1-09, CR-3·CR-4·CR-14). 상단 요약·완성도 안내·"작성 중" 배지·"작성 중인/그만둔 AI 대화" 묶음·"기타 프로젝트" 묶음을 지운다(CR-5·CR-7·CR-11).
2. **S-09·S-34·S-10 별도 편집 화면**을 상세 화면의 섹션 편집(재직/교육 정보, 근무/교육 내용, 프로젝트 정보, 프로젝트 내용, STAR 항목)으로 재정의하고, 인라인인지 모달인지 정해 `[가정]`으로 둔다. 섹션 편집 중 이탈 시 입력 보존 방식(F-P1-06)도.
3. **S-35를 프로젝트 상세 전체 페이지로 흡수**: 왼쪽 메뉴 없음, 뒤로 + 이동 경로 "{커리어명} › {프로젝트명} › 프로젝트 상세", 머리(이름·경험 유형·역량), 왼쪽 STAR 다섯 섹션(라벨 상황 / 역할 / 행동 / 결과/성과 / 배운 점, 영문 병기 여부 판단), 가운데 너비 손잡이, 오른쪽 "Resumate AI" 패널.
4. **S-36 폐기** → 패널 명세: 대화 기록 목록, + 새 대화, … 메뉴(대화 삭제 등), 닫기, 빠른 버튼 3개(PRD `[가정]`: "비어 있는 항목 채우기" / "결과·성과 구체화하기" / "지금까지 내용 STAR에 정리하기" — 문구 확정), 정리 결과 미리보기 → 확인 시 왼쪽 STAR 반영, "검토 필요" 처리, 메시지 상한 40 도달 시 같은 프로젝트의 새 대화, 키 없음 잠금 상태(3.3), 게이트(F-AP-06) 복귀 배너.
5. **새 프로젝트 흐름**(CR-6): 경력·교육 상세 "+ 프로젝트 추가" → 이름만 입력 → 작성 중 프로젝트 생성 → 프로젝트 상세로 이동. 대화로 새 프로젝트를 만드는 흐름(FL 중 "새 프로젝트" 모드)과 대화 중 소속 정하기를 지운다. 게이트(F-AP-06)·보완점(F-P2-09)에서 오는 흐름도 이 방식으로.
6. **S-11 정량 성과 화면 폐기**(CR-11). 결과 입력의 "구조화 입력 권유"도 삭제.
7. 독립 프로젝트 상세(프로젝트 정보: 기간·담당 업무·사용 기술·Link / 프로젝트 내용 / 산출물 목록 + "+ 산출물 추가") 와 산출물 보기·편집 방식(F-P1-17·18). 교육 상세 섹션 제목은 "교육 정보"(피그마 "재직 정보" 오류).
8. 프로젝트 카드(종류 태그 + 이름 말줄임 + "YYYY.MM - YYYY.MM (N년 N개월)", 2열), 분류 3종 선택 UI(종류·경험 유형 단일, 역량 복수 최대 3 — F-P1-19 `[가정]`).
9. 메뉴 이름 "자기소개서 관리"(CR-12): IA, L-01 메뉴, 이동 경로 첫 마디. 화면 안 "기업 JD" 표기 유지 여부 판단(PRD는 `[가정: 유지]`).
10. 빈 상태 문구(커리어 추가 하나), "작성 중" 배지 없이 미완료 프로젝트를 알리는 방법 제안(PRD 9.0 Q-CR-4).
11. 전체 스킬 목록의 위치(F-P1-05, 독립 프로젝트 사용 기술 + 직접 추가) — 피그마에 없음.

### ai-feature-designer (`03-ai-features.md`)
1. **AI-12 AI 작성 대화** 재설계: 항상 `project_id`에 묶임, 프로젝트당 대화 여러 개, `new_project` 모드·소속 제안·대화 중 기본 정보 수집 제거, 질문 순서 상황 → 역할 → 행동 → 결과/성과 → 배운 점, 이미 채워진 STAR를 입력으로 받아 빈 곳부터 묻기, 출력 = STAR 1개(제목 없음)의 항목별 제안, 빠른 버튼 3개의 동작 정의(PRD `[가정]`).
2. **Career Context Pack**: 상세 내용 복수 → 프로젝트당 STAR 1개, 정량 성과·경력 단위 성과 제거, 경력·교육 안 프로젝트의 `role`·스킬 제거(CR-10), 독립 프로젝트(담당 업무·사용 기술·Link·프로젝트 내용)와 **산출물(제목 + 마크다운 본문)** 추가 + 새 근거 별칭(예: `DLV-n`), 분류 3종은 참고 메타데이터로만(사실 근거 아님, PRD `[가정]`).
3. **근거 검증·숫자 가드**: 정량 성과 기준 → 결과/성과·프로젝트 내용·산출물 서술 안의 숫자 기준(NFR-AI-02, CR-11). evidence_links 대상에 산출물·프로젝트 내용 추가.
4. 인사이트(근거 단위), 경력기술서(경력별 → 프로젝트별 STAR 역할·행동·결과/성과, 독립 프로젝트는 담당 업무·내용·산출물), 자소서(배운 점 = 본인의 회고), 면접 질문(A11 사실 전제 = STAR 행동·결과/성과 + 독립 프로젝트 내용·산출물) 입력 갱신.
5. 경력 쪽 기술 키워드가 STAR 서술에서만 나오게 될 때 기술 요건 충족 판정 품질 영향 검토(PRD 9.0 Q-CR-2). 평가 세트에 해당 사례 추가 제안.
6. F-P1-08 AI 다듬기(Should)의 진입을 패널 안으로 두는 것이 맞는지 의견.

### data-architect (`04-data-model.md`)
1. STAR를 `projects`에 합칠지(결정 메모 권고) 1:1 테이블로 남길지 결정하고 근거 기록(CR-2). `project_details` 다건 구조·`title` 제거, 필드 이름 `insights`(배운 점)·`task`(역할) 정리.
2. `achievements` 테이블 폐기와 관련 FK·삭제 연쇄·근거 대상 정리(CR-11).
3. `projects.role` 필수 해제/삭제, 프로젝트-스킬 연결을 독립 프로젝트로 한정, 팀 규모·한 줄 요약(`summary` ≤200자) 처리(CR-10, PRD `[가정]`).
4. 독립 프로젝트 필드: `link`(URL 1개 `[가정]`), 프로젝트 내용(긴 본문, `summary`와 별개, 길이 상한 제안), 담당 업무, 사용 기술.
5. **산출물 새 테이블**(제목 + 마크다운 본문, 독립 프로젝트 1:N, 소유자 RLS, 삭제 연쇄, evidence_links 대상·세대 검사, 개수·길이 상한 `[가정]`)(CR-8).
6. 분류 3종 컬럼과 값 목록(text + CHECK 또는 enum), 역량 복수 저장 방식(F-P1-19 `[가정]`).
7. `writing_chats`: `mode new_project`·`project_id` NULL 허용·90일 자동 삭제(크론, D-DM-08) 폐기, 프로젝트당 다건 대화 목록 정렬 기준, 프로젝트 삭제 시 대화 연쇄 삭제(CR-6).
8. 완료 판정 트리거 재정의: 경력·교육 안 프로젝트 = 이름 + STAR(상황 + 행동), 독립 프로젝트 = 이름 + 프로젝트 내용, D-01 readiness 갱신(PRD 9.1 D-01 `[가정]`). 작성 중 프로젝트를 이름만으로 만들 수 있게.
9. 연도 묶음(D-22 개정): 독립 프로젝트 시작월 NULL 허용 시 "연도 미정" 처리, 기간 "(N년 N개월)" 계산 규칙(시작·종료월 포함)을 화면 계산인지 뷰인지.
10. 소속 변경 규칙: 경력 ↔ 교육만, 독립 ↔ 경력·교육은 불가(PRD `[가정]`).

## 사용자에게 열린 질문
- **Q-CR-1** 분류 값 목록과 선택 방식(PRD F-P1-19 `[가정]`) — 종류 9개·경험 유형 7개·역량 10개, 종류·경험 유형 단일 / 역량 복수 최대 3이 괜찮은지.
- **Q-CR-2** 경력·교육 안 프로젝트에서 사용 기술을 빼면 경력 쪽 기술 근거가 STAR 서술에만 남는다. 그대로 갈지(권고) 경력 단위 기술 태그를 둘지.
- **Q-CR-3** 독립 프로젝트: 완료 = 이름 + 프로젝트 내용, 분류 3종 없음, AI 작성 대화 없음(MVP) — 괜찮은지.
- **Q-CR-4** "작성 중" 배지 삭제 후 미완료 프로젝트를 알리는 방법(배지 없이 STAR 영역 도움말 한 줄 정도) — UX 제안을 받아 확정.
- (참고) 경력·교육 안 프로젝트의 팀 규모·한 줄 요약도 피그마에 없어 함께 뺐다 `[가정]`. 남겨야 하면 알려 달라.
