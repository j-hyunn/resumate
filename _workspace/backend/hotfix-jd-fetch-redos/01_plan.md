## 문제
`src/server/services/job-description/fetch.ts`의 HTML 정규식 8곳이 공격자가 고른 입력에서 이차~삼차 시간이 걸린다.
- 로그인한 사용자 + 공개 웹 페이지 하나면 된다.
- 540 KB에서 11.9초, 2 MB면 Vercel `maxDuration` 60초까지 막힌다.
- 동기 정규식이 도는 동안에는 **10초 deadline 타이머가 끼어들지 못한다.**
- Fluid compute에서는 같은 인스턴스의 다른 사용자 요청도 멈춘다.

| 패턴 | 증가 |
|------|------|
| 남은 태그 `<[^>]*>` · `<img…>` · `BLOCK_TAGS` · `<li\|tr\|td…>` | O(n²) |
| 주석 `<!--…-->` · JSON-LD `<script>` | O(n²) |
| 보일러플레이트 블록 `open` · iframe `src` | **O(n³)** |

## 수정
1. 태그 정규식 `[^>]*` → `[^<>]*`. 실제 HTML 출력은 바뀌지 않는다.
2. 주석·`<script>`는 `indexOf`로 끝을 찾는다.
3. O(n³) 두 곳은 선형이 되게 다시 쓴다.
4. 변환 첫 단계에서 `\u0000`을 제거한다. R15부터 NUL이 원문까지 통과해 Postgres가 거부했고, 그 결과 생성·미리 보기가 실패했다.
5. 2 MB 병적 입력에서 1초 안에 끝나는지 단정하는 테스트를 둔다.

**정상 페이지 출력은 바이트 단위로 바뀌지 않는다.** 기존 테스트는 고치지 않고 그대로 통과시킨다.
