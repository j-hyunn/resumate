## 이슈

### QA-01 [Major] 편집기에 포커스만 해도 값이 바뀌어 페이지가 dirty가 되고, 저장하면 원문과 다른 문자열이 저장됨 (항목 6)
- 담당: UI 소유 파일 → **UI 요청**(resumate-ui frontend-engineer). 백엔드 담당 없음
- 근거:
  - `doc-markdown-editor.tsx:160-165` StarterKit(`@tiptap/starter-kit` 3.32.2)은 기본으로 `TrailingNode`를 켬(`node_modules/@tiptap/starter-kit/dist/index.js:58-60`). 이 플러그인은 문서 마지막 블록이 문단이 아니면 **다음 트랜잭션 아무거나**에 빈 문단을 덧붙임(`@tiptap/extensions/dist/index.js:624-631`).
  - 포커스는 트랜잭션을 보냄(`@tiptap/core/dist/index.js:6087` `setMeta("focus")`) → 덧붙인 트랜잭션이 문서를 바꿈 → `update` 이벤트(`core:6998-7004`) → `onUpdate`(`doc-markdown-editor.tsx:180-184`)가 다시 직렬화한 마크다운으로 `onValueChange` → `project-page.tsx:199` `dirty = !same(values, baseline)`가 참.
  - 프로브 결과(편집기와 같은 확장 구성, 포커스 트랜잭션 1회):

    | 저장된 값 | 포커스 뒤 값 |
    |------|------|
    | `- 성과 A\n- 성과 B` | `- 성과 A\n- 성과 B\n\n` |
    | `* 별표 목록` | `- 별표 목록\n\n` |
    | `1) 괄호 번호` | `1. 괄호 번호\n\n` |
    | `2023. 3월 입사` | `2023. 3월 입사\n\n` |
    | `# 제목` / `> 인용` | 끝에 `\n\n` |
    | `\| a \| b \|…` (표) | 앞뒤 줄바꿈 추가 + 셀 너비 맞춤으로 다시 씀 |
    | 문단으로 끝나는 평문 | 변화 없음 (통과) |
  - 영향: 목록·제목·인용·표로 끝나는 과거 평문/마크다운(경력 문장에 흔한 `- ` 목록 포함)을 열고 클릭만 해도 저장 버튼·이탈 경고가 뜨고, 저장하면 STAR가 끝 `\n\n`과 다시 쓴 목록 기호로 저장됨(STAR 저장 경로는 trim하지 않음 — `20261110000400_r5_page_save_rpcs.sql:153`은 빈 값만 null). `?focus=` 첫 포커스·`?range=` 강조(`deliverable-page.tsx:336-341`)는 열자마자 dirty. 산출물 본문의 표가 다시 써지면 기존 `source_locator` 오프셋이 어긋남.
- 수정 제안: `StarterKit.configure({ trailingNode: false, … })` (가장 단순). 또는 `onUpdate`에서 사용자 입력이 아닌 트랜잭션(덧붙임 트랜잭션만 문서를 바꾼 경우)을 무시. 수정 뒤 "목록으로 끝나는 값 → 포커스 → `onValueChange` 없음" 테스트 추가 권장. 참고: 실제로 고친 뒤의 다시 쓰기(`* `→`- `, `a<b`→`a&lt;b`, `\n\n\n`→`\n\n`)는 편집기 의미상 예상된 동작이라 이슈 아님.
- 상태: 열림 (UI 요청으로 리더에게 넘김)
