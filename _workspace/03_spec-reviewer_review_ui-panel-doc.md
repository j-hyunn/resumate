## 이슈

### R-UP-1 [Major] 편집기의 HTML 태그 시작 `<` 이스케이프 형식이 AI C-1.1·DM 2.2와 다르다
- 경계: B3 (AI ↔ DM ↔ 구현)
- 근거:
  - `03-ai-features.md` 214행 C-1.1 "(v4.10, UP-9) 이스케이프 규칙": "서식으로 읽힐 기호(`\*`·`\_`·`\~`·`` \` ``·`\#`·`\>`·`\[` 등)와 HTML 태그 시작 `\<`만 백슬래시로 이스케이프한다 … 엔티티 디코딩은 하지 않는다(엔티티로 저장되지 않으므로)".
  - `04-data-model.md` 136행: "**서식으로 읽힐 기호와 HTML 태그 시작 `<`만** `\`로 이스케이프한다".
  - 구현 `src/components/common/doc-markdown-editor.tsx` `patchMarkdownEscaping`: `.replace(/([\\`*[\]~])/g, "\\$1")`, 단어 가장자리 `_` → `\_`, 그리고 **`.replace(/<(?=[A-Za-z/!?])/g, "&lt;")`** — 태그 시작 `<`는 **엔티티 `&lt;`** 로 저장된다. `#`·`>`는 이스케이프하지 않는다.
  - 결정 UP-9는 방식을 정하지 않았다("서식으로 읽힐 기호와 HTML 태그 시작 `<`만 이스케이프").
- 영향: C-1.1대로 "엔티티 디코딩 없음"이면 `a <div> 태그`가 정규화 평문에 `a &lt;div> 태그`로 들어가 V-3 인용·오프셋 지도가 사용자가 본 글자와 어긋난다(실행 확인: 현재 정규화 결과 `"a &lt;div&gt; tag" => "a &lt;div&gt; tag"`).
- 담당: ai-feature-designer (C-1.1이 정규화 정본). DM 2.2 한 문장은 data-architect가 따라 고친다.
- 수정 제안(권고 = 문서를 코드에 맞춤): C-1.1 이스케이프 규칙을 "편집기는 `\` `` ` `` `*` `[` `]` `~`와 단어 가장자리 `_`를 백슬래시로, 태그로 읽힐 `<`(뒤가 영문자·`/`·`!`·`?`)만 `&lt;`로 저장한다. 정규화는 백슬래시를 지우고 `&lt;`만 `<`로 되돌린다(다른 엔티티는 디코딩하지 않음)"로 고치고, `\#`·`\>` 예시는 뺀다. DM 2.2 136행도 같은 말로. (반대로 코드를 `\<`로 바꾸는 길도 있지만, 이미 저장된 값이 생겼을 수 있어 권고하지 않음.)
- 상태: 미해결
