## 5. 기획 확인 필요 (`[가정]`으로 덮지 않은 것 — 8.4에 P-28·P-29·P-30으로 등록)

1. **P-28 · C-11 "사용한 경력·프로젝트"가 보일 값** (3.10 / 플로우 S-46 자소서 탭·제안 카드 "근거 목록" 행, decisions 4.19 UI #6)
   - 문제: C-11이 선택 장치에서 **읽기 전용 목록**으로 바뀌었는데, 행에 무엇을 보일지가 명세에 없다. 옛 `role`(주 근거/보조)·`origin`(AI 선택/내가 추가)은 체크 트리와 짝이던 값이고, 플로우는 "그 문항이 쓴 경력·교육·프로젝트", "항목 → C-02", "`evidence_links` 행을 읽는다"까지만 정한다.
   - 선택지: (a) 경로 + `rationale`·관련 요건 두 줄만(지금 임시안) (b) 역할·출처 배지를 계속 보인다 — 그러면 `evidence_links` 행에 그 구분이 있어야 한다(데이터 모델 확인 필요).
   - 화면 영향: 목록 행 높이·배지 유무. (b)면 백엔드 계약도 늘어난다.
2. **P-29 · 문항 설정 상태에서 "저장하기"만 눌렀을 때의 전환 시점** (플로우 S-46 "두 상태" · 문항 설정 상태 표)
   - 문제: 정본 행은 "첫 저장하기 **또는** [자기소개서 작성 시작]"에서 생긴다. 그런데 상태 판정은 "정본 행이 있으면 작성 상태"다 — 저장하기만 눌러도 행이 생기므로 **같은 방문 중에 화면이 통째로 작성 상태로 바뀌는지**가 정해지지 않았다. 바뀌면 문항을 더 넣으려던 흐름이 끊기고 바닥의 [자기소개서 작성 시작]을 다시 볼 수 없다.
   - 선택지: (a) 같은 방문에서는 전환하지 않고(저장은 저장만) 다시 열 때 작성 상태 — 지금 임시안 (b) 저장 즉시 작성 상태로 전환하고 문항 추가는 작성 상태의 "문항 편집"에서만.
   - 화면 영향: 문항 설정 상태를 다시 볼 수 있는지, 바닥 주 버튼의 생애. (b)면 "저장하기"가 사실상 화면 전환 버튼이 되어 L-02 저장 규칙(저장은 저장만)과 어긋난다.
3. **P-30 · 작성 상태에서 문항 설정으로 돌아갈 입구** (플로우 S-46 자소서 탭 "문항 편집")
   - 문제: 문항 문장·글자 수·기준·메모는 **문항 블록 안의 "문항 편집"으로만** 고친다. 여러 문항의 글자 수만 손보려면 블록을 하나씩 열어야 한다.
   - 선택지: (a) 지금 명세대로(블록 안 편집) (b) 머리 ⋯에 "문항 설정" 항목을 두어 문항 설정 상태를 다시 연다(= 두 상태를 사용자가 왕복).
   - 화면 영향: (b)는 두 상태의 "정본 행 유무" 판정 규칙을 바꾸는 일이라 기획 결정이 필요하다.

**기획 공백은 아니지만 적어 둘 것**: 플로우 S-13 비고의 "이름 모양이 섞여 보인다"(옛 "회사명 – 포지션명"과 새 "{기업 명} 자기소개서")는 화면이 `name`을 그대로 보이는 것으로 처리했다 — 목록에서 두 모양이 섞여 보이는 것이 정상임을 A3에 적었다.
