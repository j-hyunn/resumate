## A1 변경 — 사용자 결정 (2026-11-05, 후속)

사용자가 A1을 바꿨다: **"다시 시도"를 포함한 모든 재실행은 현재 활성 공급자로 돈다.** 앞의 R-48 리더 해석(경우 ① 같은 행 다시 시도 = 처음 공급자)은 폐기한다. 표기: "확정 2026-11-05 (사용자, A1 변경)".

- 같은 작업 행 다시 시도(공용 `/api/ai-jobs/{id}/retry`: 인사이트·면접 질문 생성·채점 작업)도 다시 시도를 누른 시점의 활성 공급자·등급으로 실행하고, 작업 행의 `provider`·`model`·`connection_tier`(및 결과 행·면접 세션의 공급자 컬럼)를 그 값으로 갱신한다.
- 리더 판단(세부): 활성 공급자·등급이 작업에 기록된 것과 **다르면** 완료 단계 결과(`step_outputs`)를 버리고 처음 단계부터 다시 실행한다(한 결과가 두 공급자의 출력으로 섞이지 않게). **같으면** 지금처럼 완료 단계를 건너뛰고 이어서 한다.
- 새 작업 시작(다시 생성·다시 채점·남은 질문 다시 만들기·요청 범위 작업 다시 시도)은 원래대로 활성 공급자.
- 연결 확인은 모든 경우 활성 공급자 기준: 활성 공급자 키 없음 → "AI 연결 필요", 무효 → 키 교체, 활성 공급자·등급 동의 필요(A20) → 동의(C-21)를 **활성 공급자·등급으로** 연다. 다시 시도 라우트의 409 `ai_consent_required`도 활성 공급자·등급 기준.
- 화면: "처음 실행한 {공급자}로 다시 해요" 같은 문구와 S-40의 "실패한 작업의 다시 시도는 원래 공급자로" 안내를 없앤다. 대신 다시 시도 버튼 옆 배지는 활성 공급자를 보이고, 처음과 다르면 "{활성 공급자}로 처음부터 다시 해요"를 붙인다.
- 진행 중(running) 작업은 그대로 시작 공급자로 끝까지 간다("공급자 변경은 다음 실행부터" 유지 — 다시 시도는 다음 실행이다).
- 백엔드 후속 ★ 추가: 구현은 작업에 고정된 옛 공급자로 다시 돈다 → 활성 공급자로 바꾸고, 공급자가 다르면 `step_outputs`를 비우는 처리.
- 리더 판단 (R-63, 2026-11-05): 같은 행 다시 시도에서 공급자·등급이 작업에 기록된 값과 달라 처음부터 다시 돌면, 그 작업이 이미 저장한 결과 행(면접 질문, 답변 평가, 종합 등)도 모두 다시 열어 새 실행 결과로 덮어쓴다. 한 결과에 두 공급자 출력이 섞이지 않게 하려는 것. 비교 기준은 "작업 행에 기록된 값"(R-66).
